The gap between a model's best and worst task measures how hard the tasks are, which is not jaggedness.
I was wondering what metric we could use for jaggedness, here is one that shows how uneven the model is between tasks.

First, the share of models that fail an evaluation is difficulty. Now if you sort every check from the one most models pass to the one most fail, and a smooth model passes a block on the left and fails the rest. The jaggedness metric J counts how often a model breaks that order from easy to hard tasks.

<StaircaseBreak />

Take every pair of checks where i is easier than j, with p the share of its runs that passed each:

<div class="not-prose my-8 flex items-center justify-center gap-3 text-[17px]">
  <span>J =</span>
  <span class="inline-flex flex-col items-center">
    <span class="px-2 pb-1">Σ (1 − p<sub>i</sub>) p<sub>j</sub></span>
    <span class="border-t border-ink px-2 pt-1">Σ [ (1 − p<sub>i</sub>) p<sub>j</sub> + p<sub>i</sub> (1 − p<sub>j</sub>) ]</span>
  </span>
</div>

The top is failing the easier check and passing the harder one. The bottom is every pair where it passed one check and failed the other, either way round.
So 0 is a perfect staircase the model passes easy tasks and fails difficult ones and 0.5 is a model which fails disregarding how difficult the task is.

<Staircase />

The p column says whether a J could be luck: shuffle which checks a model passed and see how often J lands as far from 0.5. So far only GLM 5.3 FlashX is clearly off 0.5, and it is smooth, so the board cannot yet call any model jagged.

Some models are great at doing hard things but poor at doing things that most models find easy.

Perceptron Mk1.5 gets a dash: it passes only the easiest check, and one pass only says where that check sits on the ladder. So J needs a model to pass and fail at least two checks each, which is where the metric stops working for very weak models.
